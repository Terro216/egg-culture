# План поздравления Дмитрия Фонина

## Контекст

Проект: «Яичная Культура» (`egg-culture`).

Цель: добавить в блог поздравительную статью для Дмитрия Фонина — одного из основателей культуры и одного из первых, кто разглядел глубину желтка. Из статьи пользователь попадает в закрытую часть сайта, проходит уже существующую «Инициацию Адепта», а затем открывает персональную кладку подарков.

Основной маршрут:

1. `/ru/blog/dmitry-fonin-visionary` — статья-поздравление.
2. Ссылка из статьи ведёт на `/ru/dark-side/fonin`.
3. Если `localStorage.egg_adept !== "true"`, страница отправляет на `/ru/quiz` и запоминает целевой путь в `localStorage.egg_after_quiz`.
4. После успешного квиза пользователь возвращается на `/ru/dark-side/fonin`.
5. На странице кладки нужно ввести кодовое слово и пройти три испытания с датчиками телефона.
6. После каждого успешного испытания серверный API возвращает содержимое соответствующей карточки.

## Кодовое слово

Кодовое слово хранится в `.env`:

```env
FONIN_ACCESS_WORD="Ча Ци"
```

По умолчанию, если переменной нет, сервер принимает `Яй Ци`.

Проверка выполняется через серверный endpoint:

- `src/pages/api/fonin-access.ts`

Важно: кодовое слово не должно быть захардкожено в клиентском JS. Клиент отправляет введённое слово на сервер, сервер сравнивает его с `FONIN_ACCESS_WORD`.

## Подарки

Сейчас реальных сертификата два. Третий подарок — сюжетная заглушка про чайного гномика.

Реальные сертификаты хранятся картинками в приватной директории:

```text
/home/me/server/projects/egg-culture/private/fonin-gifts/gift-1.png
/home/me/server/projects/egg-culture/private/fonin-gifts/gift-2.png
```

Env-переменные `FONIN_GIFT_1_CERTIFICATE`, `FONIN_GIFT_2_CERTIFICATE`, `FONIN_GIFT_3_CERTIFICATE` больше не нужны.

Желательно добавить секрет для подписи временных ссылок:

```env
FONIN_GIFT_TOKEN_SECRET="длинная-случайная-строка"
```

Если `FONIN_GIFT_TOKEN_SECRET` не задан, подпись строится от `FONIN_ACCESS_WORD`.

Третий этап всегда возвращает текст:

> Этот подарок украл чайный гномик. Но мы обязательно поймаем его и через суд получим всё обратно. Думаю, управимся к следующей встрече.

Выдача содержимого карточек происходит через endpoint:

- `src/pages/api/fonin-gifts.ts`

API проверяет:

- кодовое слово;
- ID подарка;
- номер этапа;
- score испытания.

Для первых двух подарков API возвращает временную подписанную ссылку на картинку сертификата:

```text
/api/fonin-gift-image?id=first-steep&token=...
/api/fonin-gift-image?id=second-dome&token=...
```

Срок жизни ссылки сейчас — 10 минут.

## Где безопасно хранить картинки сертификатов

Не класть сертификаты в:

- `public/`;
- `src/`;
- markdown;
- клиентский React state;
- lazy-loaded chunk;
- репозиторий.

Все эти варианты либо публичны, либо легко вытаскиваются из HTML/JS/network.

### Рекомендуемый вариант для текущего проекта

Используется приватная директория вне публичной раздачи:

```text
/home/me/server/projects/egg-culture/private/fonin-gifts/
  gift-1.png
  gift-2.png
```

Директория `private/` добавлена в `.gitignore`.

Серверный endpoint:

```text
/api/fonin-gift-image?id=first-steep&token=...
```

Он:

1. Проверяет `id` подарка.
2. Проверяет HMAC-подписанный временный `token`.
3. Проверяет срок жизни ссылки.
4. Читает файл из `private/fonin-gifts/`.
5. Возвращает картинку с `Cache-Control: no-store`.

Так сертификаты не лежат в публичном web root, не попадают в клиентскую сборку и не открываются по прямому `/private/...` URL.

### Альтернативы

1. **Private object storage + signed URL**
   - S3/YC Object Storage/любой S3-compatible storage.
   - Файлы приватные.
   - Сервер выдаёт короткоживущую signed URL после прохождения этапа.
   - Это самый аккуратный вариант, если хочется нормально хранить файлы.

2. **Хранить как base64 в `.env`**
   - Не рекомендуется для картинок: большие env, неудобно менять, легко сломать деплой.
   - Подходит только для очень маленьких секретных строк, не для изображений.

3. **Telegram-бот**
   - Бот проверяет Telegram ID Дмитрия и присылает картинки напрямую.
   - Самый сильный вариант по адресности, но добавляет отдельную инфраструктуру.

## Текущая механика трёх испытаний

Компонент:

- `src/features/GiftVault/GiftVault.tsx`
- стили: `src/features/GiftVault/GiftVault.css`

Страница:

- `src/pages/[lang]/dark-side/fonin.astro`

### Этап 1 — «Чахай и пиала»

Идея: оставить чайный элемент, но не чайник. Телефон становится чахаем, из которого нужно плавно налить настой в пиалу.

Механика:

- сначала пользователь кладёт телефон на стол;
- калибруется нулевое положение;
- потом пользователь плавно наклоняет телефон вправо;
- на экране заполняется пиала;
- если наклон слишком сильный или заполнение ушло выше порога — «пиала перелита»;
- успех — наполнить пиалу примерно до нужного уровня и вернуть телефон ровно.

Ключевые параметры в коде:

- угол начала налива: около `10°` по `gamma`;
- опасный угол: около `58°`;
- целевое заполнение: примерно `0.78–0.96`;
- перелив: `fill > 1.03` или `spill > 0.32`.

После успеха открывается первая печать.

### Этап 2 — «Халаза-тест»

Идея: использовать яичную механику. На экране — яйцо в стиле `MonumentalEgg`, которое нужно удержать в центре.

Источник визуальной идеи:

- `src/shared/ui/MonumentalEgg/MonumentalEgg.astro`

В React-компоненте используется похожая Three.js-сцена: деформированная сфера с белым физическим материалом, мягким светом и золотым акцентом.

Механика:

- пользователь нажимает `Положить на стол`;
- сразу открывается fullscreen-игра;
- внутри fullscreen идёт калибровка baseline;
- fullscreen не закрывается после калибровки;
- внутри fullscreen появляется кнопка `Начать испытание`;
- яйцо само начинает медленно укатываться из центра;
- даже если телефон идеально неподвижен, в симуляции есть drift;
- пользователь ловит яйцо наклоном телефона;
- нужно удержать яйцо в центральной зоне несколько секунд;
- зона засчёта расширена именно в игровой логике (`CHALAZA_CENTER_RADIUS = 0.48`), а не только визуально;
- визуальная центральная зона тоже увеличена, чтобы соответствовать более мягкому засчёту;
- игра проигрывается только когда яйцо касается прямоугольной рамки fullscreen-арены (`x/y` достигают `CHALAZA_FRAME_LIMIT = 1.08`);
- при проигрыше яйцо не трескается, а укатывается за кадр;
- fullscreen остаётся открытым после неудачи, можно нажать `Начать испытание` ещё раз;
- fullscreen закрывается только при успешном прохождении или по кнопке `Закрыть испытание`;
- для мобильной высоты используется `100dvh`, чтобы кнопки не уезжали под строку браузера.

После успеха fullscreen закрывается и открывается вторая печать.

### Этап 3 — «Оракул желтка»

Идея: сделать понятную отсылку к Magic 8 Ball, но в яичной эстетике.

Механика:

- на экране желтковый шар с цифрой `8`;
- пользователь нажимает «Спросить оракула»;
- нужно один раз встряхнуть телефон;
- слишком слабый встрях — «Оракул не почувствовал вопрос»;
- слишком сильный — «Оракул увидел омлет»;
- правильный диапазон открывает третью печать.

Третий этап возвращает историю про чайного гномика вместо сертификата.

## Мобильные нюансы

Целевой телефон: Samsung / Android.

Ожидания:

- лучше всего открывать в Chrome или Samsung Internet;
- сайт должен быть открыт по HTTPS;
- датчики `deviceorientation` / `devicemotion` обычно работают проще, чем на iOS;
- если события не приходят, UI показывает подсказку проверить HTTPS, браузер и доступ к датчикам.

Для iOS предусмотрен вызов `DeviceOrientationEvent.requestPermission()`, если метод существует.

## Безопасность и ограничения

Текущая защита — подарочная, не банковская:

- квиз Адепта;
- кодовое слово;
- прохождение motion-этапов;
- сертификаты не лежат в клиентском JS;
- содержимое карточки отдаёт сервер.

Что не защищено идеально:

- если человек знает кодовое слово и может пройти этапы, он сможет получить содержимое;
- без серверной сессии/БД нельзя строго зафиксировать «только один раз»;
- motion-score можно потенциально подделать из консоли, потому что браузерный клиент контролирует отправляемые данные.

Если нужно усилить:

1. Добавить серверную сессию после `fonin-access`.
2. Хранить прогресс этапов на сервере.
3. Отдавать подарок только если предыдущие этапы реально отмечены сервером.
4. Для картинок использовать приватный файловый endpoint или signed URLs.
5. Максимальная адресность — Telegram bot / Telegram Login с проверкой `telegram_id` Дмитрия.

## Что важно помнить при деплое

После изменения `.env` нужно перезапустить Astro/контейнер, иначе сервер может продолжить использовать старые переменные окружения.

Если сертификаты будут храниться локальными файлами, не класть их в `public/`. Использовать `private/` или директорию вне проекта и серверный endpoint для выдачи.
