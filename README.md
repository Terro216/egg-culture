# Яичная Культура (Egg Culture)

Гастрономический и эстетический манифест, возводящий куриное яйцо в ранг спешалти-кофе, коллекционного вина и элитного китайского чая. Ироничный по замыслу, абсолютно серьезный в подаче.

Сайт: `https://egg.<DOMAIN>` (по умолчанию — https://egg.ilyamedve.dev)

Полное описание концепции, философии и архитектуры — в [EGG.md](EGG.md). Исторический план проекта — в [PROJECT_PLAN.md](PROJECT_PLAN.md). Механика закрытой «кладки Фонина» — в [FONIN_PLAN.md](FONIN_PLAN.md).

## Стек

- **Astro 7** — статика (SSG) по умолчанию + SSR-адаптер `@astrojs/node` (standalone) для динамических страниц (`/blog`, `/prophecy`, `/dark-side/fonin`, API-роуты). Блок игр на `/dark-side/` проверяет статус адепта на клиенте.
- **React 19** — точечные интерактивные острова (Island Architecture).
- **Three.js** — 3D-яйцо, шейдеры тёмной стороны и трасса «Пути формы».
- **Rapier 3D (WASM)** — физика асимметричного яйца в «Пути формы», целиком в браузере.
- **d3-geo + topojson-client** — векторная карта терруаров.
- **@resvg/resvg-js** — серверный рендер og-карточек результата теста «Какое вы яйцо?» (SVG → PNG, шрифты в `src/shared/assets/fonts`).
- Нативный Astro i18n (`ru`/`en`) + собственная утилита переводов, без клиентских i18n-библиотек.
- Архитектура — Feature-Sliced Design (`app / pages / widgets / features / shared`).

## Великая Жарка

Публичная игра без Инициации: `/ru/fry/` и `/en/fry/`. Тот же компонент
доступен из Зала испытаний. Старт — 10 яиц; рекорд — доставленная на сковороду
кладка. Общий аккаунт связывает игры, гостевой рекорд остаётся в браузере.
Текущий зачёт и коды дорог — `FRY3`; обновление ворот не сбрасывает прогресс.

С шестого участка встречаются дробные выражения: красное `÷(2/4)` даёт рост,
зелёное `×(0,8)` — потерю. Цвет обозначает операцию, а не её выгодность.
Редкий тройной ряд содержит фиолетовый `?` посередине: частичный выигрыш,
частичная потеря или усиление. Эффект воспроизводится по сиду; боковые ворота
позволяют отказаться от риска. Такие ряды не появляются на раздельных дорогах.
Кнопка `?`, ↓ или S направляет в центр; отмена ворот отключает весь ряд.

Кухонное окружение меняет палитру каждые три участка. Конвейеры, печи,
мешалки, вентиляторы и пар собраны в шесть фиксированных instanced-пакетов;
декорации следуют пройденному расстоянию. «Меньше движения» останавливает
дополнительные анимации, сохраняя движение мира по дороге.

Проверки: `npm run check:games`, `npm test`; браузерные сценарии
`scripts/verify-fry-public.mjs`, `scripts/verify-fry3-mechanics.mjs` и
`scripts/verify-fry-late.mjs` запускаются только на изолированном loopback-preview.

## Книга Кладки

В `/ru/kladka/` и `/en/kladka/` автор выбирает аудиторию записи: «Для всех»
или «Только адептам». Выбор сохраняется при премодерации и виден Хранителю
в Telegram. Старые формы без `visibility` создают общедоступную запись.
В ленте помечаются только закрытые записи; у общедоступных нет плашки аудитории.

У закрытой записи неофит видит автора, дату и приглашение пройти Инициацию
с возвратом к этой записи. Текст, стиль и фотография не входят в HTML или
ответ `/api/kladka-feed`; `/api/kladka-image` также проверяет доступ.
У аккаунта проверяется облачный статус Инициации, у гостя — существующая
cookie `egg_guest_initiated`; сохранённый `egg_adept` восстанавливает её
при открытии Книги. Гостевая отметка не открывает записи аккаунту неофита.
Лента и фотографии отдаются с `private, no-store` и `Vary: Cookie`.

## Яичные игры

Главная ведёт одной кнопкой «Яичные игры» в `/ru/games/` и `/en/games/`.
Каталог использует общий `AdeptGames`: «Путь формы», «Великая Жарка» и
«Халазы судьбы» открываются на своих общедоступных страницах; Халаза-тест
и Оракул желтка показывают замок до Инициации. После теста пользователь
возвращается к выбранному испытанию. Статус проверяется через общий Portal:
гостевая отметка не открывает игры вошедшему аккаунту неофита, потеря доступа
закрывает активное испытание. Тяжёлые игровые модули загружаются при запуске.

Сверху `GamesAccount` раскрывает существующую форму входа и регистрации прямо
в каталоге; код восстановления остаётся видимым до подтверждения. Внизу —
«Пройти Инициацию» и «Читать Манифест». Страницы трёх открытых игр содержат
обратную ссылку на каталог. На главной калькулятор подписан «Сварить яйцо».

## Испытания адептов

Блок на `/ru/dark-side/#games` и `/en/dark-side/#games` содержит Халаза-тест,
Оракул желтка, **«Путь формы» / Path of Form**, Великую Жарку и Халазы судьбы. Старые адреса
`/dark-side/games/` перенаправляются в этот блок. Доступ проверяется
по облачному статусу Инициации в профиле; для гостей — по `egg_adept`
в браузере (сессионная cookie служит запасным вариантом при недоступном storage). Игры загружаются по выбору; Three.js и Rapier для
дороги не входят в начальную загрузку зала. Общие испытания не используют
приватные подарки или API кладки Фонина.

Полная игра также доступна без Инициации на `/ru/play/` и `/en/play/`.
В неё можно перейти из каталога «Яичные игры»; внизу страницы и меню
есть приглашение к Инициации. Используется тот же компонент и то же хранилище,
что и в Зале испытаний. Ссылки на сиды ведут на публичную страницу.

«Путь формы» — спуск по дороге над Пустотой с приземлениями на нижние витки.
Яйцо — динамическое твёрдое тело с выпуклой асимметричной оболочкой;
центр масс и моменты инерции вычисляет Rapier по этой форме. Видимая модель
повторяет физическое вращение, без случайных толчков или скрытого шара.
Это модель цельного твёрдого яйца: жидкий желток и разрушение скорлупы
не симулируются. Непредсказуемость управления возникает из формы и контактов.

В меню есть учебная трасса, последовательное прохождение уровней, бесконечный
режим и ввод сида. Учебная карта — прежние четыре витка, около 857 м. В уровнях
после финиша открывается следующая процедурная карта с петлями, разворотами
и S-образными участками; проверяется зазор между пересечениями. Прогресс
кампании хранится в `egg_road_journey_v1`. Учебные и импортированные карты
не меняют достигнутый уровень.

«Осмотреть ещё раз» плавно отводит камеру назад, затем вращает её вокруг карты.
Карту можно вращать пальцем или мышью по обеим осям, на клавиатуре — стрелками
или WASD. После ручного движения выбранный ракурс сохраняется; «Сбросить обзор»
плавно возвращает исходный ракурс и автоматическое вращение. Масштаб сохраняет
всю карту в кадре, вертикальный угол ограничен от −14° до 77°.
Яйцо неподвижно, обзор продолжается до нажатия «Подлететь и начать» или пробела.
Подлёт занимает 4,6 секунды, его можно пропустить. При `prefers-reduced-motion`
переходы мгновенные, автоматическое вращение выключено; ручное доступно.
Быстрый повтор сохраняет выбранную карту.

Сиды вида `EGG1-R-2-ABC` содержат версию генератора, вид дороги, уровень и
32-битное зерно в base36. `R` — отдельная карта, `E` — бесконечная дорога.
Можно скопировать код или ссылку `?road=...`, сохранить карту в браузере,
ввести код либо ссылку. Сохранённые карты лежат в `egg_road_maps_v1`; старые
не вытесняются автоматически. Версию `EGG1` нужно сохранять при будущих
изменениях генератора либо поддержать её отдельно, чтобы старые коды работали.

Для ручной проверки поворотов и подскоков подходит `EGG1-R-2-GRIP`
(`/${lang}/play/?road=EGG1-R-2-GRIP`): около 896 м, разгон, правый виток
и чередование левых и правых дуг. Первая смена стороны — около 251 м от начала.
Это обычный воспроизводимый сид генератора `EGG1`; повтор открывает ту же трассу.

Бесконечная дорога генерируется из сида по участкам с общими вершинами стыков.
Вокруг игрока остаётся до четырёх участков: один позади и два впереди.
Геометрия и коллайдеры пройденных участков удаляются; физика, скорость и очки
на стыке не сбрасываются. Плавающее начало координат сохраняет точность Rapier
в долгих заездах. Повтор восстанавливает начало той же последовательности.

Отметка даёт 100 очков. Дополнительные очки: движение по краю (+14/м),
скорость от 23 м/с (до +20/м), ритм от двух перекатов (+2 × серия/м, до +20/м),
высокое падение от 12 м (+3/м высоты после приземления) и срезки (+35 за
пропущенную отметку). Нужны физический контакт и новое продвижение по трассе;
повторный проезд одного места и неудачное падение бонусов не дают. Итоговый
экран показывает разбивку. В HUD — личный рекорд текущего сида, ключ
`egg_road_track_points_v1`. Учебная карта в разных режимах имеет один рекорд,
а конечная и бесконечная дороги с одинаковым зерном — разные. На карточке
в Зале — только рекорд бесконечного режима из `egg_road_points_v2`. Старые
рекорды без сида не приписываются отдельным картам.

Ритм учитывает небольшое реальное боковое перемещение и чередование поправок
курса, в том числе торможение бокового сноса. В EGG3 минимум — 0,12 с управления
и 4 см бокового пути; требования к вращению нет. Пауза в управлении до 0,6 с
сохраняет незавершённый перекат. Каждый удачный перекат добавляет 18% заряда.
Через 0,65 с без удачного переката заряд плавно убывает на 70% в секунду;
при полном разряде серия обнуляется. Частое нажатие без реального переката
не даёт бонуса. Перекаты также дают короткий импульс разгона,
ограниченный целевой скоростью. Звук при включённом аудио и короткая вибрация
при поддержке браузером позволяют следить за дорогой. Яйцо не подсвечивается
и не меняет свой материал при наборе ритма.
Индикатор показывает заряд и серию без подсказок момента смены стороны.
Базовая целевая скорость — 18,5–21,5 м/с, с небольшой прибавкой по сложности;
бонус ритма — `заряд × 8 × log2(1 + серия / 8)` м/с, без потолка серии.
Старые коды EGG1/EGG2 сохраняют прежний набор и затухание заряда с бонусом
до 9 м/с. Подробности: [настройка ритма](docs/egg-road-dynamic.md). При вылете
с дороги заряд, серия и время переката замораживаются: управление в воздухе
не заряжает ритм, после приземления он продолжается. Короткие подскоки яйца
над полотном остаются частью обычного переката. После вылета даётся 4,2 с
на возвращение; обычные подскоки
над полосой не включают предупреждение. Физика идёт с шагом 1/120 с и CCD.
Коллайдер яйца использует вершины видимой модели, у дороги есть физические
боковины и нижняя поверхность.

Обычные подскоки также сохраняют силу поворота: до 25 м/с² при полном вводе,
даже когда яйцо уже вне зоны близкого контакта. Настоящий полёт и спасательный
прыжок используют прежние 11 м/с². Автоматического бокового торможения нет:
поправка действует только по вводу игрока; форма, вращение и отскоки остаются физическими.

Вся левая и правая половины экрана, включая область под HUD, работают как
кнопки поворота. Короткое касание даёт небольшую поправку, удержание набирает
полную силу за 0,18 с — тянуть палец для усиления больше не нужно. Переход
пальца через середину меняет направление; два пальца на разных половинах
взаимно отменяются. Прыжок, обзор и кнопки HUD имеют отдельные зоны.
Отпускание, отмена жеста, поворот экрана, пауза и потеря фокуса прекращают
подруливание. `←`/`→` и `A`/`D` используют тот же разгон силы. Ритм принимает
и мягкие поправки (от 10% силы), но по-прежнему требует реального бокового пути.
Осмотр — потянуть
`◎`, удерживать `Q`/`E` или включить «Обзор наклоном». Наклон и его калибровка
меняют только камеру: оси движения и силы физики от них не зависят.
Ручной обзор доступен на 200° вправо и влево: перетаскивание `◎` прямо меняет
угол, отпускание сохраняет ракурс. `Q`/`E` постепенно поворачивают камеру;
нажатие `◎` или `C` плавно возвращает взгляд вперёд. Чувствительность жеста
снижается к краям диапазона, скорость поворота ограничена. Наклон сохраняет
прежнюю чувствительность и калибровку при возврате взгляда.
Автоматическая камера поворачивается по углу с ограничением скорости и ускорения;
смена направления почти на 180° не даёт скачка через нулевой вектор.
Камера следует за фактической горизонтальной скоростью яйца на дороге и в воздухе,
включая движение назад относительно полотна. Разворот более чем на 90° должен
продержаться 0,16 с; при скорости ниже 3 м/с направление сохраняется. Короткие
удары не переворачивают обзор, а устойчивое движение не ждёт приземления.
В полёте камера отдаляется с 12 до 18 м, поднимается, расширяет поле зрения
и смотрит ниже.
При видимом прогнозе наклон плавно удерживает в кадре яйцо и точку касания,
не меняя горизонтальное направление обзора.
После 0,55 с устойчивого возвращения на полотно плавно восстанавливается
обычная дистанция обзора. Короткие касания и повторные вылеты сохраняют
расширенный кадр. Сильное приземление также включает это ожидание:
контакт после полёта более 0,45 с со скоростью к поверхности более 12 м/с.
Положение и цель камеры используют общую опорную точку с отставанием до 2 м:
поворот проходит по дуге вокруг яйца, а после удара камера не проваливается под него.
Подсказка приземления по умолчанию выключена; переключатель в меню и на паузе
сохраняется в браузере. Кольцо без стрелки показывает оценку первого контакта
только после 0,75 с настоящего полёта, при движении вниз быстрее 4 м/с и перепаде
не менее 8 м от вершины полёта до прогнозируемого касания. Мелкие подскоки
и приземление сразу скрывают кольцо; выключенная подсказка не вычисляет прогноз.
Прогноз проверяет текущую форму яйца, вращение, силу и гравитацию
на горизонте до 2,4 с с шагом 0,08 с, десять раз в секунду. Он не меняет
физический мир и не предсказывает последующие отскоки или будущие нажатия.
Стрелочный спидометр со шкалой 0–160 км/ч показывает горизонтальное перемещение:
падение, вертикальный отскок и вращение на месте не добавляют скорости.
Цифровое значение показывает фактическую скорость и за пределами шкалы.
Один заряд прыжка доступен кнопкой `↑` или `Space`, в том числе в воздухе.
Он гасит отрицательную вертикальную скорость и добавляет 6 м/с вверх.
Горизонтальная скорость снижается на четверть по фактическому направлению
движения, независимо от камеры и последнего участка дороги; направление
и вращение сохраняются. Это разовое торможение: в полёте авторазгон выключен,
после приземления обычный разгон возвращается. Ритм на время прыжка заморожен.
Каждый успешный прыжок полностью обновляет таймер возвращения до 4,2 секунды,
сохраняя высоту падения и историю очков. Заряд восстанавливается
за 6 секунд езды со скоростью более 3 м/с по дороге. Мелкие подскоки оболочки
считаются продолжением езды; настоящий полёт, спасательный прыжок, остановка
и пауза замораживают таймер. Остаток времени и прогресс видны на кнопке.
Посадка сама по себе заряд не возвращает, очки и новые участки бесконечной
трассы не влияют на таймер. Новая попытка или следующий уровень дают полный заряд.
Кнопка калибровки есть в меню и во время спуска («Ноль»). Разрешение датчика
запрашивается по нажатию, при отказе остаётся ручной обзор. `P`/`Esc` — пауза,
`R` — повтор, `Space` во время подлёта — пропустить его. Горячие клавиши отключены в меню
и при вводе сида. Потеря фокуса ставит игру на паузу. Звук выключен по умолчанию;
его настройка остаётся в `egg_road_v1`.

На телефоне при первом выборе карты или запуске заезда игра запрашивает
полный экран и горизонтальную ориентацию. На загрузке страницы браузер не
разрешает такой запрос без пользовательского нажатия. Кнопка поворота в HUD
и меню переключает горизонтальный/вертикальный вид, запоминает выбор и ставит
текущий заезд на паузу. Используется `screen.orientation.lock` после fullscreen;
если браузер не поддерживает блокировку, поворачивается сама игровая область.
Координаты касаний, камера, safe area и компактный HUD учитывают этот поворот.
Кнопка полного экрана и `F` остаются доступны; `Esc`/выход ставит заезд на паузу
и снимает блокировку ориентации. Возобновление не заставляет входить снова.
На горизонтальных экранах до 560 px высотой HUD собран в компактные верхнюю
и нижнюю полосы, кнопки учитывают вырезы и safe area. Поворот устройства
и смена размера не перезапускают заезд. В Safari на iPhone вместо недоступного
element fullscreen показана инструкция «Поделиться → На экран Домой».
У `/ru/play/` и `/en/play/` свои web app manifest, иконки и режим `standalone`;
запуск с домашнего экрана убирает панели браузера. Офлайн-режим не заявлен.

После заезда можно явно опубликовать результат под именем (до 32 знаков).
`GET/POST /api/egg-road-records` возвращает таблицу для канонического сида:
20 лучших игроков и собственное место, даже если оно за пределами двадцатки.
Одна запись на игрока и сид, обновление только при улучшении; одинаковые очки
дают одинаковое место. Имя и очки публичны, идентификатор игрока — нет.
Имя уникально для игрока на всём сайте: NFKC-нормализация, регистр и повторные
пробелы не позволяют занять то же имя повторно. Занятое имя возвращает HTTP 409;
можно выбрать другое и повторить публикацию того же заезда. Смена гостевого имени
обновляет все таблицы игрока, даже если новый заезд слабее прежнего рекорда.
Занятие имени и запись результата выполняются одной SQLite-транзакцией.
Старые совпадающие имена получают числовой суффикс при первом открытии базы;
очки и места сохраняются. Это уникальность ника, а не проверка личности:
визуально похожие буквы разных алфавитов могут выглядеть одинаково.
Можно играть гостем: случайная HttpOnly/SameSite-cookie на год, в базе только
её SHA-256. Для доступа на других устройствах в меню игрока есть регистрация
по имени и паролю, без почты. При регистрации из того же браузера опубликованные
рекорды атомарно переходят в аккаунт, имя закрепляется и больше не меняется
через отправку результата. Старый гостевой идентификатор заменяется случайным
внутренним ID; старая cookie не даёт доступа к аккаунту даже при откате образа.
Вход использует отдельную HttpOnly/Secure/SameSite-cookie `__Host-egg_road_session`
на 30 дней; в SQLite хранится только хеш токена. До 10 сеансов на аккаунт.
В dev используется cookie без префикса `__Host-` для локального HTTP.

`GET/POST /api/egg-road-account` поддерживает `register`, `login`, `logout`,
`change`, `recover`. Пароль — от 15 до 128 Unicode-символов, без обрезания
и требований к набору символов; scrypt N=131072, r=8, p=1, индивидуальная соль.
Одновременно выполняются не больше двух операций scrypt. Регистрация выдаёт
случайный 160-битный код восстановления (только его SHA-256 в базе); он показывается
один раз и доступен для копирования или скачивания. Смена пароля требует текущий
пароль, восстановление — имя и код. Обе операции отзывают все прежние сеансы
и заменяют код восстановления. Пароль и код не сохраняются в localStorage.
Без обоих восстановить доступ нельзя; подтверждения личности или почты нет.
Гостевое имя, опубликованное до регистрации, можно закрепить только из его
исходного браузера. Локальные очки разделены по аккаунтам; при регистрации
текущие гостевые очки копируются в новый профиль. Карты и прогресс кампании
остаются локальными. Вход в существующий аккаунт показывает его серверные
рекорды; опубликованные записи другого гостя автоматически не объединяются.
Игра работает и при недоступной таблице, личные результаты сохраняются локально.

В меню есть вкладка популярных трасс с фильтрами обычных и бесконечных дорог.
`GET /api/egg-road-records?view=popular&mode=all|finite|endless` возвращает до
20 сидов по числу разных игроков с опубликованным результатом. Повторные
попытки одного игрока не добавляют популярности. При равенстве выше трасса
с более свежим рекордом. Карточка запускает тот же сид в обоих языках сайта.
Один аккаунт учитывается один раз даже при входе с нескольких устройств.
Гости с разными cookie считаются отдельными игроками. Это не счётчик просмотров
или подтверждённых людей; полной защиты от массового создания игроков нет.

Сервер хранит записи в SQLite `.kladka/egg-road/records.sqlite` внутри уже
существующего тома `kladka_data`; переопределение — `EGG_ROAD_DATA_DIR`.
Исходные посты и фотографии Кладки не меняются. База использует DELETE journal
и FULL synchronous; для согласованной резервной копии работающей БД используйте
SQLite backup API или `VACUUM INTO`, не копируйте открытый файл произвольно.
`npm test` пишет только во временные каталоги. `.kladka` исключена из Docker build.
Для локальной проверки API задавайте `EGG_ROAD_DATA_DIR` в `/tmp`.

Проверка длины конечной дороги выполняется отдельным Node worker thread:
`scripts/road-validation-worker.mjs` использует тот же генератор из `src/`, что
и игра. Один worker принимает до восьми различных ожидающих кодов, объединяет
повторные запросы одного кода и кэширует 128 длин. При заполненной очереди API
возвращает временную ошибку 503; геометрия и границы старых сидов не меняются.
Runtime должен содержать `scripts/`, `src/` и зависимости; текущий Dockerfile
уже копирует их. Для Node 22.13 явно включено `--experimental-strip-types`.

POST требует origin сайта и JSON, ограничен 8 КБ и 20 запросами/минуту с IP;
GET — 120/минуту. Исходные IP не сохраняются, ограничители используют хеши.
Для аккаунтов отдельные лимиты: 30 запросов с IP и 20 на имя за 15 минут,
состояние хранится в SQLite и переживает рестарт. Все изменения требуют
origin сайта и JSON, включая вход и выход; пароли и токены не журналируются.
Проверяются сид, имя, конечные числа, согласованность дистанции, отметок и суммы
бонусов. Это защита входных данных, а не серверная проверка прохождения:
результаты рассчитываются клиентом и могут быть подделаны модифицированным
клиентом. Серверного воспроизведения заездов и соревновательного античита нет.

Для игры нужен WebGL2. `tests/egg-road*.test.mjs` проверяют настоящую WASM-физику,
стыки и длительное продолжение бесконечной дороги, воспроизводимость сидов,
разделение режимов, защиту очков от повторного проезда, реальное приземление
и езду по краю, раскачивание, прыжок на земле и в воздухе, плавность обзора,
датчики и калибровку. `check:games` проверяет
игровые модули. В браузере дополнительно сравниваются физические траектории
при одинаковом управлении с наклоном и без него, проверяются подлёт, повторный
обзор, освобождение WebGL-ресурсов, мобильный интерфейс и ссылки на карты.
Чувствительность датчика и частоту кадров нужно оценить на настоящих телефонах.
`npm run check` сначала генерирует типы Astro, затем проверяет TypeScript всего сайта.
CI запускает установку по lockfile, обе проверки типов, тесты, сборку и audit зависимостей. Docker использует `npm ci`
без запасной установки зависимостей, чтобы релиз точно соответствовал lock-файлу.

## Переменные окружения

Смотри `.env.example`:

- `DOMAIN` — базовый домен (сайт живет на поддомене `egg.`). Compose передаёт
  его и как Docker build argument: при смене домена нужна пересборка образа
  (`docker compose build web`) перед согласованным пересозданием контейнера.
  Это сохраняет одинаковый origin в canonical URL, sitemap и защите POST.
- `NEWS_API_KEY` — ключ [NewsData.io](https://newsdata.io) для мировой яичной ленты в блоге. Без ключа используется `demo`; если провайдер недоступен, сайт отдаёт сохранённую ленту или пустой список. Устаревший кэш показывается сразу, обновление идёт в фоне. Успешный пустой результат также соблюдает суточный TTL; при сбое интервал повторов растёт с минуты до часа и сохраняется в `news_cache` между перезапусками.
- `FONIN_ACCESS_WORD` — кодовое слово закрытой кладки подарков.
- `FONIN_GIFT_TOKEN_SECRET` — секрет подписи временных ссылок на сертификаты (если не задан — используется кодовое слово, задать настоятельно рекомендуется).
- `FONIN_GIFT_PRIVATE_DIR` — путь к директории с PNG-сертификатами (по умолчанию `private/fonin-gifts`).
- `KLADKA_BOT_TOKEN`, `KLADKA_ADMIN_CHAT_ID` — Telegram-бот премодерации Книги Кладки (`/kladka`): записи прилетают админу с кнопками «Одобрить/Отклонить». Ответы забирает встроенный long poller `scripts/kladka-poller.mjs` и передаёт локальному API; публичный Telegram webhook не используется. Без токена записи публикуются сразу. Опционально: `KLADKA_WEBHOOK_SECRET` (подпись внутреннего вызова poller → API), `KLADKA_IP_SALT`, `KLADKA_DATA_DIR`.
- В личном чате модератором считается его владелец. В группе проверяется статус
  `creator`/`administrator` через Telegram `getChatMember`; сбой проверки повторяется
  poller-ом. Необязательный `KLADKA_ADMIN_USER_IDS` — список Telegram user ID через
  запятую для явного делегирования модерации вместо проверки статуса. Callback
  всегда должен относиться к настроенному `KLADKA_ADMIN_CHAT_ID`.

После изменения `.env` контейнер нужно **пересоздать**: обычный
`docker compose restart` не перечитывает `env_file`.

```sh
docker compose up -d --force-recreate web
```

## Халазы судьбы

`/ru/untangle/` и `/en/untangle/` — самостоятельная головоломка семейства
Untangle/Planarity, доступная также из списка испытаний адептов.
24 ступени, общая кладка дня (00:00 по Москве), произвольные сиды `NEST1`,
ссылки на одинаковую задачу и результаты. Яйца перемещаются мышью, пальцем
или клавиатурой; есть отмена/возврат, пауза и отмеченные подсказки.

Партия сохраняется в браузере отдельно для каждого аккаунта. Завершённые
задачи, рекорды ходов/времени и шесть достижений используют общий профиль
и его очередь синхронизации. Сервер повторно строит граф и проверяет решение.
Незаконченная раскладка остаётся локальной; публичный профиль содержит
только суммарные результаты. [Исследование, архитектура и проверка](docs/egg-untangle.md).
