# Комиссия по форме / The Form Commission

Игра об инспекторе, который проверяет партии яиц, применяет регламент
и отвечает за свои решения. Маршруты — `/ru/commission/` и `/en/commission/`.
Игра не включена в навигацию сайта и не индексируется. Это скрытая ссылка,
а не парольная защита: открыть игру может любой, у кого есть адрес.

## Игровой цикл

Кампания состоит из двенадцати смен. Игрок осматривает образец, сравнивает
измерения с паспортом и выбирает решение: принять, обоснованно отклонить,
отложить или поручиться. Инструменты расходуют рабочее время по действиям;
чтение документов и вращение образца не запускают обратный отсчёт.

Пять инструментов — осмотр, весы, овоскоп, проба и реестр. Они показывают
измерения и признаки; наблюдение записывает сам игрок. Подготовка инструмента
оплачивается один раз и сохраняется при перезагрузке. Неверное измерение
или версия документа оцениваются при подписании решения.

После смены доступны отчёт, последствия, апелляции и вечерние решения.
Досье содержит необязательное расследование: вывод требует подтверждения
независимыми документами. Кампания поддерживает разные концовки и увольнение.

Ежедневная смена воспроизводима по московской дате, использует одинаковое
оснащение и серверную проверку результата. Публикация в таблице ежедневных
результатов выполняется явно; достижения кампании остаются внутри игры.

## Сохранения и API

`storage.ts` сохраняет журнал действий локально. `engine.ts` воспроизводит
его и проверяет допустимость переходов. Старые действия `tool` и `file`
остаются совместимыми с новыми `prepare`, `examine` и `connect`.

Облачное сохранение использует существующую сессию аккаунта и
`src/pages/api/commission.ts`. Серверная часть — `src/server/commissionStore.ts`.
Она проверяет владельца, Origin, размер запроса, версию сохранения и журнал
действий. Конфликт версий требует явного выбора; повтор сетевого запроса
не должен затирать более свежую партию.

Гость может играть локально, экспортировать сохранение и явно перенести его
в свой аккаунт. Переключение аккаунта не переносит чужой прогресс. Незавершённые
партии и достижения не публикуются в общем профиле. HTML и API отдают
директивы `noindex, nofollow, noarchive` и приватное кэширование.

## Карта кода

Клиентские модули находятся в `src/features/Commission/`:

| Модуль | Ответственность |
| --- | --- |
| `cases.ts`, `content.ts` | Дела, персонажи, регламент и RU/EN |
| `engine.ts`, `types.ts` | Состояние, действия, последствия и replay |
| `examination.ts` | Измерения и проверка наблюдений |
| `storage.ts`, `useCommission.ts` | Локальное и облачное сохранение |
| `Specimen.tsx`, `Workbench.tsx` | Образец и инструменты |
| `Dossier.tsx` | Документы и выводы расследования |
| `Commission.tsx`, `Commission.css` | Игровой интерфейс |

## Проверка

```sh
node --experimental-strip-types --test tests/commission-*.test.mjs
```

Тесты проверяют кампанию, концовки, нарушения, отложенные дела, поручительство,
апелляции, воспроизводимость дня, старые сохранения, неверные измерения,
границы ввода, конфликты и изоляцию аккаунтов.

`scripts/verify-commission.mjs` и `scripts/verify-commission-workbench.mjs`
проверяют реальное управление в браузере. Они требуют изолированный
loopback-preview. `PLAYWRIGHT_MODULE` задаёт модуль Playwright,
`CHROMIUM_EXECUTABLE` — браузер, `COMMISSION_PREVIEW` — адрес preview.
Прогоны с регистрацией используют только тестовую базу.

При изменении интерфейса проверьте обе локали, ширины 320/390 px и desktop,
клавиатуру, все инструменты, reload, полную смену, восстановление сети
и явный выбор при конфликте сохранений.
