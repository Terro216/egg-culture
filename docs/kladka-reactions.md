# Реакции в Книге Кладки

Под записью видны счётчики и кнопка «Реакция / Reaction». Панель предлагает
пять реакций: 🥚 крепкая скорлупа, 💛 в самый желток, 🐣 вылупился от смеха,
🔥 греет и 🍳 аппетитно. Можно выбрать до трёх разных реакций на запись.
Собственные реакции выделены; повторное нажатие снимает только выбранную.
Панель остаётся открытой для нескольких нажатий и показывает число выбранных
реакций. При достижении лимита нужно снять одну, чтобы добавить другую.
Русский и английский интерфейсы одинаковы
по возможностям, управление доступно с клавиатуры и на сенсорном экране.

## Кто может реагировать

Нужны действующий сеанс общего аккаунта и сохранённая на сервере Инициация.
Новый аккаунт может реагировать сразу после Инициации, без периода ожидания.
Гостевой флаг Инициации не даёт права голосовать. Панель объясняет следующий
шаг. Счётчики открытых записей доступны без входа. У закрытых записей
реакции скрыты вместе с содержимым; ожидающие и отклонённые записи недоступны.

## Ограничения и границы защиты

Ключи SQLite не допускают повтор одного emoji от аккаунта на запись. Лимит
в три реакции проверяется атомарно в транзакции и дополнительно ограничен
схемой хранения. API устанавливает желаемое состояние отдельной реакции,
поэтому повтор запроса после потери ответа не добавляет голос и не снимает
его случайно. Изменения других реакций из соседней вкладки не затираются. Смена устройства
или IP не меняет идентичность аккаунта. Переданная клиентом личность не
авторизует запрос: сервер проверяет сеанс и совпадение текущего аккаунта.

| Ограничение | Значение |
| --- | --- |
| Разные реакции от аккаунта на запись | 3 |
| Изменения с одного аккаунта | 20 в минуту, 200 за 24 часа |
| Изменения из одной сети | 60 в минуту, 500 за 24 часа |
| Разные аккаунты на одну запись из одной сети | 5 за 24 часа |
| Попытки запросов из одной сети | 120 в минуту на процесс |

Лимит выбора и ограничения изменений сохраняются в базе и проверяются атомарно вместе с
записью. Окно начинается с первого действия, а не с полуночи. Снятие реакции
не освобождает место для другого аккаунта в сетевом лимите. Повтор уже
сохранённого состояния не расходует лимит изменений. Общая сеть семьи или
организации также подпадает под сетевой лимит; ответ сообщает время повтора.

Проверяются Origin, JSON Content-Type, размер и схема тела, существование и
доступность записи. Произвольные emoji и клиентские счётчики не принимаются.
Ответы персонализированной ленты не кэшируются. Имена реагировавших, IP и
идентификаторы аккаунтов других читателей в API не выдаются.

Это ограничение стоимости накрутки, а не доказательство «один человек — один
аккаунт». Заранее подготовленные аккаунты с разных сетей нельзя надёжно
отличить от разных людей без дополнительной проверки личности. Счётчики не
следует использовать как основание для выдачи наград или других ценностей.

## Прокси и хранение

`KLADKA_REACTION_PROXY_HOPS=0` по умолчанию использует адрес соединения и
игнорирует `X-Forwarded-For`. Compose задаёт `1`: web не публикует порт и
доступен через Caddy. Берётся последний адрес цепочки, добавленный этим
прокси, а не произвольный первый адрес. При изменении топологии нужно
проверить границу доверия; включать доверие заголовкам у публичного web-порта
нельзя. [Caddy описывает обработку forwarded-заголовков](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults).

IPv4-mapped IPv6 приводится к IPv4, адреса IPv6 одной `/64` используют общий
лимит. В базе хранится только HMAC адреса или подсети со случайным ключом,
созданным в этой же базе. Сетевые записи истекают через сутки и очищаются при
следующем изменении реакции; старые снимки могут сохранять их до истечения
срока хранения резервных копий.

Таблицы `kladka_reactions`, `kladka_reaction_extras`, `kladka_reaction_limits`,
`kladka_reaction_networks` и `kladka_reaction_settings` создаются при открытии
существующей `records.sqlite`. Новый том и внешняя служба не нужны.
Резервирование SQLite автоматически включает реакции, лимиты и HMAC-ключ.
Уже поставленные реакции сохраняются без переписывания. Первая реакция
остаётся в исходной таблице, ещё две — в дополнительной. Старая версия
приложения при откате продолжает читать первую реакцию и менять её; триггеры
согласованно снимают дополнительные при таком изменении. Старые открытые
вкладки сохраняют прежнюю механику одного выбора; после обновления доступны три.
